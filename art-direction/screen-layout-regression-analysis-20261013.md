# 20261013-13 화면 배치 회귀 원인 분석

이번 화면 이상은 사운드 재생을 위해 추가한 WebView의 바깥 컨테이너를 게임 배치에서 제외하지 않은 구현 결점이다. 사용자 기기·캐시 문제를 원인으로 돌릴 근거가 없다.

## 확인 근거

1. `TemporarySfxPlayer.tsx:40`은 WebView를 직접 반환하고 `style`에만 `position:absolute, width:1, height:1`을 지정한다. `containerStyle`은 지정하지 않았다.
2. 설치된 `react-native-webview/src/WebView.ios.tsx:199-200`은 안쪽 WebView의 style과 바깥 View의 containerStyle을 별도로 합친다. 286행에서 바깥 View를 반환한다.
3. `WebView.styles.ts:4-7`의 바깥 기본값은 `{flex:1, overflow:'hidden'}`이다. 안쪽을 1픽셀로 만들어도 바깥 View는 일반 배치 안에서 높이를 차지한다.
4. `P0GameScreen`은 사운드 플레이어를 HUD 앞의 첫 자식으로 배치한다. 경기장도 `flex:1`이다. 따라서 사운드의 빈 바깥 컨테이너와 경기장이 남은 높이를 나눠 가지며 HUD가 아래로 밀린다. 제공된 두 사진의 큰 상단 여백과 작은 경기장은 이 구조와 일치한다.

## 같은 원인으로 이어지는 증상

- 경기장 높이가 줄어 상대 캐릭터의 화면 채우기 SVG(`xMidYMid slice`)가 세로로 더 많이 잘린다. 사진 2의 상대 얼굴 잘림을 별도 이미지 누락으로 해석할 근거는 없다.
- 시작 화면에서는 경기장 안의 고정 크기 시작·기록 버튼이 공간을 먼저 쓰며, 위쪽 스크롤 안내 영역이 압축된다. 사진 1에서 관장 대사·사용법이 가려진 현상과 일치한다.
- 이번 사진에서 양손 글러브는 표시된다. 화면 전체 배치 실패와 글러브 이미지 누락은 구분해야 한다. 사진만으로 실제 효과음 출력 성공 여부는 확인할 수 없다.

## 재현과 이전 검증의 결함

`webview-container-diagnostic-20261013.test.tsx`에서 설치된 실제 iOS WebView의 JavaScript 래퍼를 실행했다. 네이티브 모듈·네이티브 뷰만 대체하여 바깥 래퍼 구조를 보존했다.

- 현재 설정: 안쪽은 absolute 1×1이지만, 실제 바깥 스타일은 `{flex:1, overflow:'hidden'}`이고 position/height는 없다.
- 비교 설정: 바깥 containerStyle도 absolute 1×1·flex:0으로 지정하면 바깥 컨테이너의 일반 배치 공간이 제거된다.
- 두 진단 조건 통과. 실제 iPhone의 Yoga 픽셀 좌표를 측정한 테스트는 아니며, SDK 래퍼의 잘못된 유효 스타일을 직접 재현한 것이다.

기존 오디오 테스트는 WebView 전체를 단일 `<View {...props}/>`로 대체했다. 실제 바깥 컨테이너를 없애 버렸으므로 이번 결점을 검사할 수 없었다. 게임 화면 테스트도 사운드 플레이어 자체를 대체한다. AIT 검사는 새 코드·음원 포함 여부를 검사했지만 바깥 레이아웃의 공간 점유를 검사하지 않았다. 따라서 이전 246개 통과와 빌드 성공은 화면 배치 정상의 증거가 아니었다.

## 최소 수정 방향과 현재 범위

- 사운드 플레이어의 바깥 컨테이너까지 absolute·고정 크기·flex:0으로 격리하거나, absolute 컨테이너 아래에 전체 WebView를 넣어 일반 게임 배치에서 제외한다. 경기장·캐릭터·안내 크기를 임의로 늘려 보상하는 수정은 원인을 해결하지 않는다.
- 회귀 검사에서는 실제 SDK 래퍼를 보존하고 바깥 컨테이너의 유효 스타일을 확인해야 한다. 실제 기기에서는 시작 전·경기 중·소리 끄기/켜기·광고 복귀에서 HUD 위치와 경기장 크기가 유지되는지 확인해야 한다.
- 이번 요청은 원인 분석이므로 진단 자료만 추가했다. 앱 소스·배포 AIT를 수정하거나 새 빌드·업로드·검수·출시를 진행하지 않았다.
