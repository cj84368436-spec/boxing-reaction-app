## 출시 전에 해결할 결점

### 1. HIGH: 닫힘 뒤 도착한 보상 이벤트를 잃음

`src/app/ads/rewardedRetryAd.ts:94`, `:100`, `:108`: dismissed에서 즉시 settled=true로 확정하고 다음 광고를 로드한다. 이후 같은 광고의 userEarnedReward는 settled 또는 generation 검사에서 무시된다.

재현: `node art-direction/ad-event-audit.cjs`. 보상→닫힘은 continued=1, 닫힘→보상은 continued=0. 사용자가 보상 조건을 충족했어도 이벤트가 역순이면 재도전 권리가 사라지는 코드 경로가 확인됐다. 실제 토스 기기에서 역순 이벤트가 발생했는지는 미확인이다.

[Google 공식 문서](https://developers.google.com/admob/android/rewarded)는 Google 공급 광고는 보상이 먼저지만, AdMob 미디에이션 광고의 콜백 순서는 제3자 광고 공급자에 달려 있다고 설명한다. 설치된 토스 SDK 2.10.10은 닫힘과 보상 이벤트를 그대로 전달하며 앱에 전달하기 전 순서를 재정렬하지 않는다. 토스의 모든 광고에서 역순 발생을 확정하는 근거는 아니다.

보완 방향: 광고 시도별 보상과 닫힘을 따로 추적하고, 닫힘 직후 지연 보상을 처리할 수 있게 유지한다. userEarnedReward 없이 닫았다는 이유만으로 보상하지 않으며 중복 보상·이전 광고의 늦은 이벤트·화면 이탈도 함께 처리해야 한다.

### 2. MEDIUM: 광고 콜백 미수신 시 자동 복구가 없음

`src/app/ads/rewardedRetryAd.ts:154`, `src/app/screens/P0GameScreen.tsx:299`, `:449`: load 이후 loaded/onError가 오지 않으면 loading에서 벗어나지 않는다. 재도전 버튼은 ready/error에만 활성화된다. showing에서도 종료·실패 이벤트가 없으면 복구되지 않는다. `src/app/ads/stageInterstitialAd.ts:48`, `:75`도 show 이후 이벤트가 없으면 다음 단계가 대기한다.

가짜 포트가 아무 콜백을 보내지 않는 재현에서 보상형 phase=loading 또는 showing, continued=0이 유지됐다. 실기기에서 콜백 유실이 발생했다고 단정하지 않는다. 난이도 선택을 통한 화면 복귀는 남아 있으므로 앱 전체가 완전히 잠긴다는 뜻도 아니다.

보완 방향: 로드에 제한 시간을 두고 재시도 가능한 오류로 전환한다. 표시 중에는 시간이 지났다는 이유만으로 새 경기를 시작하지 말고, 광고 종료·앱 활성 상태를 확인해 안전하게 복구해야 한다. SDK 반환 cleanup은 콜백 해제이며 실제 광고를 닫는 기능이 아니다.

## 전체 흐름 검토와 기존 검증

- 루트 진입은 P0GameScreen 직접 연결이며 비교 서버 주소는 전달하지 않는다. 공개 온라인 경쟁 기능은 현재 출시 진입에서 노출되지 않는다.
- 기록 읽기 실패 시 기존 저장값을 덮어쓰지 않고, 손상값 백업 실패 시 저장을 중지한다. 저장 순서는 직렬화되어 있다. 완주 승급·최고 기록 유지·백그라운드 일시정지·음소거 처리와 관련 테스트를 검토했다.
- 정상 광고의 보상+닫힘은 재도전을 한 번만 실행한다. 조기 닫힘에는 보상하지 않는다. 전면형 로드 실패·미지원·표시 실패는 다음 단계로 진행한다. 해제 뒤 늦은 콜백 방어도 있다.
- 같은 대화에서 최종 404 수정 상태로 실행한 `npm.cmd test` 222개, `typecheck:app`, `build:app` 통과 증거를 사용했다. 읽기 전용 검토 중 전체 테스트·빌드를 다시 실행하지 않았다. 이번 추가 실행은 광고 이벤트 재현과 산출물 정적 검사다.
