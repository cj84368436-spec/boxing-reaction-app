# 10펀치 플레이 흐름 수정

## 확인한 원인
이전 화면에서 Ready 머리 x는 잽 175.45, 스트레이트 67.99, 훅 161.31이었다(화면 폭 280). 공격별 impact 손 위치에 단순 평행 이동하던 방식 때문에 상대 위치가 최대 107.46만큼 달라졌다. 기존 원근식과 glove 크기 상한은 접근감을 제한했고, 렌더링 테스트는 사람의 공격 식별 가능성을 검증하지 않았다.

## 적용
- 원본 19관절, FK, 공격 정의, 고정 시퀀스와 입력 판정은 보존했다.
- firstPersonPresentation에서 Ready와 contact로 한 번 보정한 고정 원근 카메라를 사용한다. 모든 Ready 머리는 (140,100), contact 손은 (140,165). 카메라의 높이·방향·원근 거리만 보정하며 motion pose와 궤적은 수정하지 않는다.
- 리그 관절 연결부를 이어 그리고 의복·팔·장갑의 레이어를 분리했다. 장갑은 기준 44의 최대 1.5배(66)다. 하체 중 정강이와 발만 전투 화면에서 숨긴다.
- 공격 손 외곽선과 최근 90ms 궤적, 접촉 효과, 얼굴 표정을 브라우저와 RN에서 함께 표시한다. 잘못된 왼쪽 훅 회피는 contact 반경을 벗어나지 않는 22의 이동, 정상 슬립은 64의 이동, 오른쪽 훅 위빙은 추가로 -80의 수직 이동이다. 이는 판정 규칙을 설명하는 프레젠테이션이며 물리 충돌 엔진을 새로 도입한 것은 아니다.
- RoundClock 하나로 엔진과 애니메이션을 함께 구동한다. 여유 모드 속도 0.65, 원래 속도 1. 여유 모드 입력 구간은 실제 시간 기준 잽 507.7ms, 스트레이트 553.8ms, 훅 615.4ms다. 원본 timing 설정은 그대로다.
- 자동 시작을 제거하고 시작 안내, 2초 준비, 네 가지 한국어 조작, 여유 모드의 공격 안내, 결과 설명, 재도전, 속도 재선택을 연결했다.
- 화면 이탈/일시 정지 시 시계를 정지하고 명시적인 계속하기를 제공한다. 입력 직전 엔진 시간을 갱신한다.
- 피격/안전/완벽 회피의 진행 표시 색을 구분하고 일반 화면에서 raw telemetry를 제거했다. 디버그 반응시간은 실제 시간 단위로 환산하고 정수로 표시한다.

## 검증
- npm test: 기준 엔진/원본 데이터 47개 + 앱 58개 통과.
- typecheck:app 통과. build:app RN 0.84/0.72 Android/iOS 번들 및 .ait 생성 성공. 배포하지 않았다.
- test:preview 6개 통과. 앱 빌드 후에도 .preview-dist의 브라우저 모듈이 모두 로드되는지 확인했다.
- Edge 브라우저: 명시적 시작, 여유 속도, 일시 정지/재개, 10개 판정, 훅 오답, 무입력 피격, 가드/뒤로 방어, 결과 색상, 동일 seed 재도전, 320×568에서 버튼 영역을 확인했다. 실행 오류 없음.
- 실제 시계를 사용하는 추가 자동 실행에서 공격 안내가 나타난 뒤 300ms 후 입력하는 조건으로 10개 PERFECT를 기록했다. 화면 안내를 이용한 기능 검사이며 사람의 시각 인지/재미를 증명하지 않는다.
- 테스트 스크립트와 화면 증거: 작업공간 .video-review/playable-check.cjs, live-check.cjs, round-*.png 및 round-*.log.
- 앱인토스 Sandbox 실제 기기 검증과 사용자 체감 품질은 미검증이다. 배포 가능한 제품 완료로 선언하지 않는다.
